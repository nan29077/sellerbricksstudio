# 스토리지마켓 (STORAGE MARKET)

라이브 커머스 셀러를 위한 **창고·스튜디오 예약 → 상품 선택/상품번호 부여 → 라이브 판매 → 주문/Mock결제 → 자체송출/카카오 알림톡** 올인원 플랫폼.

외부 API 키(PG, 카테노이드, 카카오 알림톡)가 없어도 **Mock 어댑터**로 전체 플로우가 동작합니다.

---

## 기술 스택

- **Frontend/Backend**: Next.js 14 (App Router) + React 18 + TypeScript
- **Styling**: Tailwind CSS + shadcn 스타일 컴포넌트 + lucide-react
- **DB**: PostgreSQL (docker-compose)
- **ORM**: Prisma
- **Auth**: NextAuth(Auth.js) Credentials + JWT 세션
- **Validation**: React Hook Form 호환 + Zod
- **Data**: Server Components + TanStack Query
- **외부연동**: Adapter 패턴 (PaymentAdapter / CatenoidAdapter / KakaoAlimtalkAdapter) — 키 없으면 Mock 동작
- **실시간**: 상품번호 변경 폴링(`numberVersion`) 기반 즉시 반영

## 빠른 시작

### 1. 의존성 설치

```bash
npm install
```

### 2. 환경변수 설정

```bash
cp .env.example .env
```

`.env`에서 최소 `DATABASE_URL`, `NEXTAUTH_SECRET`만 채우면 됩니다.
(나머지 PG/카테노이드/카카오 키는 비워두면 자동으로 Mock 동작)

```env
DATABASE_URL="postgresql://sellerbricks:sellerbricks@localhost:5432/sellerbricks?schema=public"
NEXTAUTH_SECRET="아무_긴_랜덤_문자열"
NEXTAUTH_URL="http://localhost:3007"
NEXT_PUBLIC_APP_URL="http://localhost:3007"
```

### 3. DB 띄우기 (Docker)

```bash
npm run db:start     # Docker Desktop + Postgres 16 자동 시작 (db-start.bat). npm run dev 도 시작 전에 자동으로 DB 를 켭니다
```

### 4. 스키마 적용 + 시드 데이터

```bash
npm run db:push      # Prisma 스키마를 DB에 반영
npm run db:seed      # 테스트 계정/창고(스튜디오)/상품 생성
```

> 마이그레이션 이력을 남기려면 `npm run db:push` 대신 `npm run db:migrate` 사용.

### 5. 개발 서버 실행

```bash
npm run dev
```

→ http://localhost:3007

### 브랜드샵과 창고(스튜디오)샵

1. 기존 개발 DB에 새 역할과 테이블을 추가하려면 `npm run db:push`를 실행합니다.
2. 브랜드사 테스트 로그인 후 샵을 만들고 공급 단가·재고, 샘플 단가·재고를 입력합니다. 샘플 단가를 비우면 미제공, 0원이면 무료입니다.
3. 최고관리자의 **브랜드샵 관리**에서 공개를 승인합니다. 셀러와 창고 관리자는 **브랜드샵**에서 공급 신청 또는 샘플 주문을 진행하고 **내 브랜드 신청**에서 상태를 확인합니다.
4. 유료 샘플은 플랫폼에서 결제되고(결제 어댑터), 브랜드가 반려하거나 발송 전에 취소하면 자동 환불됩니다. 샘플 구매는 판매 상품 가져오기와 별개로 진행합니다. 창고 입고(위탁) 요청은 브랜드 공급가 기준이며 정산은 플랫폼이 합니다.
5. 창고 관리자는 **창고(스튜디오)샵 관리**에서 공간별 디자인을 편집하고 **상품 관리**에서 예약용 판매 상품을 등록합니다. 셀러는 창고샵에서 상품을 예약에 담거나 예약 화면에서 직접 선택합니다. 최고관리자는 **창고(스튜디오) 관리**에서 샵과 상품을 편집할 수 있습니다.

샵 배너와 PC 여백은 `public/images/shop-artwork/`의 ImageGen 프리셋 또는 직접 입력한 이미지 주소를 사용합니다. 각 샵에서 배너와 여백을 개별적으로 선택할 수 있습니다.

## 브랜드 판매 연결 · 발주서 · 플랫폼 정산 · 예약 고도화 (2026-11)

> 기존 개발 DB에 반영: `npm run db:push` (새 테이블·컬럼과 예약 상태 `NO_SHOW` 추가, Prisma Client 재생성) 후 개발 서버를 다시 켜세요. 기존 데이터는 그대로 유지됩니다.

### 전체 흐름
1. **브랜드사 가입**: 브랜드(회사)명 · 사업자번호 · 취급 카테고리(17개 대분류, `src/lib/categories.ts`)를 고르면 브랜드샵이 **승인 대기**로 함께 만들어집니다. 셀러 · 창고(스튜디오)도 가입 때 관심 카테고리를 고를 수 있습니다.
2. **브랜드 상품**: 공급가 · 권장 소비자가 · 세부 카테고리 · 옵션(`색상:블랙,화이트|사이즈:S,M`) · 추가 이미지 · 출고 소요일 · 판매 방식(브랜드 직배송 / 창고 입고 허용) · 샘플 단가(비우면 미제공, 0원 무료) · 계정당 샘플 한도.
3. **샘플**: 무료 샘플은 바로 신청, 유료 샘플은 **플랫폼에서 결제**(결제 어댑터)되고 브랜드가 반려하거나 발송 전에 취소하면 자동 환불됩니다. 브랜드 화면에서 신청자 정보(라이브 횟수 · SNS 팔로워)와 **판매 전환**(판매 목록에 담았는지 · 판매 수량)을 볼 수 있습니다.
4. **판매 상품으로 가져오기** (브랜드샵 상품 카드)
   - 셀러: 브랜드 직배송 상품으로 가져와 **라이브 판매 상품 선택 → 브랜드 상품** 탭에서 방송에 올립니다. (`/seller/brand-products`)
   - 창고(스튜디오): **직배송** 또는 **창고 입고(위탁)** 중 선택. 위탁은 브랜드에 입고를 요청 → 브랜드 승인·발송 → 창고가 **입고 확인**하면 창고 판매 재고가 늘어납니다. (`/facility/brand-products`)
5. **발주서 자동 생성**: 구매자 결제가 끝나면 브랜드 × 배송방식별로 발주서가 만들어져 브랜드사로 갑니다(`/brand/orders`, 엑셀 CSV 다운로드). 직배송은 구매자 배송지로 브랜드가 출고(운송장 입력)하고, 주문 전체가 직배송이면 주문 상태도 함께 바뀝니다. 위탁 상품은 창고가 주문을 발송·완료하면 발주서가 따라갑니다. 주문 취소 · 환불 시 발주 취소 · 재고 복구도 자동입니다.
6. **플랫폼 정산** (`/admin/payouts`): 배송 완료 주문을 셀러 × 창고(스튜디오)별 **판매 정산서**로, 배송 완료 발주 + 발송된 유료 샘플을 브랜드별 **브랜드 정산서**로 묶어 확정 → 지급합니다. 판매 금액 = 플랫폼 판매 수수료 + 브랜드 공급대금 + 셀러 몫 + 창고 몫 (`src/lib/settlement.ts`).
7. **최고관리자 정책** (`/admin/policy`): 판매 수수료 · 브랜드 수수료(브랜드별 예외는 브랜드샵 관리) · 샘플 수수료 · 셀러 몫 · 예약 대기 자동 만료 · 노쇼 기준 · 이용 전 알림 · 발주 확인 권장 시간 · 샘플 주문당 최대 수량. 발주 관리(`/admin/purchase-orders`)에서 모든 발주의 상태 · 운송장 · 메모를 바꿀 수 있습니다.

### 예약 고도화
- **시간대 막기**: 일정 관리에서 하루 중 일부 시간만 막을 수 있습니다(매주 반복 가능). 셀러 화면에는 표시되지 않고 예약도 거절됩니다.
- **자동 처리**: 승인 대기 자동 만료(기본 48시간 · 시작 시간 경과), 종료된 승인 예약 자동 이용 완료, 이용 전 알림. 화면을 열 때 가볍게 실행되고, 외부 스케줄러는 `Authorization: Bearer $CRON_SECRET` 으로 `/api/cron/bookings` 를 호출하면 됩니다(최고관리자 예약 현황의 "자동 처리 실행" 버튼도 있음).
- **체크인 · 노쇼**: 창고(스튜디오)가 시작 2시간 전부터 체크인, 시작 n분 후 미체크인 예약은 노쇼 처리(잘못 처리하면 이용 완료로 되돌리기). 예약 목록에 셀러의 노쇼 · 취소 이력이 표시됩니다.

### 점검
`scripts/simulate-brand-flow.mjs` 는 가입 → 상품 → 샘플 → 가져오기 → 입고 → 예약 → 방송 → 결제 → 발주 → 배송 → 정산 → 예약 자동화 → 역할별 화면까지 135개 항목을 실제 API로 확인합니다. (테스트 데이터를 만들므로 개발 DB에서만 실행)

## 전체 플로우 체험 (5분)

1. **창고(스튜디오) 관리자**로 로그인 → `상품` 메뉴에서 상품 등록 (시드에 이미 존재)
2. **셀러**로 로그인 → `예약` → 창고(스튜디오) 검색 후 예약 신청
3. **창고(스튜디오) 관리자**로 로그인 → `예약 관리`에서 **승인**
4. **셀러**로 로그인 → `라이브` → 승인된 예약으로 **라이브 세션 생성**
5. `판매 상품 선택`에서 창고(스튜디오) 상품 추가 → **상품번호 자동/수동 부여**, 드래그로 순서 변경, 방송 중 **임시상품 추가**
6. 세션 상세에서 **방송 시작** + **카카오 알림톡 발송**(Mock) + 구매자 링크 복사
7. 구매자 링크(`/live/...`)를 새 창에서 열어 **상품번호로 장바구니 담기 → Mock 결제 → 주문 완료**
8. **셀러/창고(스튜디오) 관리자/관리자** 대시보드에서 주문·매출·정산 확인

> 셀러 화면에서 상품번호를 바꾸면 구매자 화면에 약 4초 내 자동 반영됩니다(폴링).

### 운영 흐름 (추가)

- **창고(스튜디오) 등록**: 창고(스튜디오) 관리자 → `창고(스튜디오) 등록` 메뉴에서 신청 → 최고관리자 `창고(스튜디오) 관리`에서 **승인 / 운영 정지 / 운영 재개**
- **주문 처리**: 셀러·창고(스튜디오) 관리자·최고관리자의 `주문` 화면에서 **상품 준비 → 발송 처리 → 배송 완료**, 배송 전 **주문 취소**(결제 취소 + 재고 복구), 배송 후 **환불**
- **구매자 주문 조회**: `/order-lookup`에서 주문번호 + 연락처로 조회
- **회원 정지**: 최고관리자 `회원 관리`에서 계정 정지/활성화 (정지 즉시 로그인·이용 차단)
- **중간관리자 등록**: 최고관리자 `회원 관리` → `중간 관리자 등록` (담당 창고(스튜디오) 이름이 하나와 일치하면 자동 연결)

## 사용자 역할 & 권한 (RBAC)

- **SUPER_ADMIN**: 전체 데이터, 창고(스튜디오) 승인, 중간관리자/수수료 설정, 연동·감사로그
- **MANAGER**: 본인이 영업한 창고(스튜디오)(`manager_facilities`)만 조회 — 수수료는 최고관리자만 설정
- **FACILITY_ADMIN**: 본인 소유 창고(스튜디오)/상품/예약/주문만 관리, 방송 중 상품 추가
- **SELLER**: 본인 예약/방송/상품번호/주문/정산
- **BUYER**: 공개 방송 링크 + 본인 주문 결과

권한 체크는 모든 API Route/Server Action에서 `requireRole()` / 소유권 검증으로 적용, 주요 변경은 `audit_logs`에 기록됩니다.

- 중간관리자는 `manager_facilities`에 연결된 창고(스튜디오)만 접근

## 2026-11 예약 시스템 고도화 · 이용료 무료 전환 (적용 방법)

DB 스키마가 바뀌었습니다. 한 번만 아래 순서로 실행하세요.

```bash
npm run db:push                             # 예약 정책·예약 상품·대기 신청 테이블 반영 + Prisma Client 재생성
npx tsx prisma/backfill-free-booking.ts     # 기존 요금·이용료 0원 처리 + 기존 예약에 예약번호 부여
```

> `prisma/backfill-booking-price.ts`(이용료 소급 계산)는 더 이상 쓰지 않습니다. 실행해도 안내만 출력합니다.

### 정책
- **창고(스튜디오) 이용료는 무료**입니다. 예약 이용료(`totalPrice`)는 항상 0으로 저장되고, 화면의 이용료 표시는 "무료"로 바뀌었습니다.
- 창고(스튜디오)는 **판매 상품을 등록**하고, 셀러는 **등록된 상품을 보고 그 창고(스튜디오)를 예약**합니다.

### 셀러
- **판매 상품 둘러보기** (`/seller/products`): 모든 창고(스튜디오)의 판매 상품을 검색·카테고리·지역·유형·재고로 거르고, 많이 예약된 순·수수료 순 등으로 정렬. 상품을 수량과 함께 담으면 창고(스튜디오)별로 묶어 바로 예약.
- **예약 신청 4단계** (`/seller/bookings/new`): 장소 → 판매 상품·수량 → 일정 → 확인
  - 4주 여유 달력(여유 / 마감 임박 / 마감 / 휴무), 이용 시간 선택, 시작 시간 버튼(예약 가능 / 승인 대기중 / 예약됨), 타임라인
  - **정기 방송**: 매주 같은 요일·시간으로 최대 12주. 날짜별 가능 여부를 미리 보여주고, 안 되는 날짜만 빼고 예약 가능
  - **대기 신청**: 다른 셀러가 잡은 시간에 대기 → 그 예약이 취소·거절·변경되면 알림
  - 완판 시 매출·예상 셀러 수익 요약, 즉시 확정 공간은 바로 확정
- **예약 관리**: 예약번호, 판매 예정 상품(준비 가능/불가 표시), **일정 변경**(같은 화면에서 빈 시간 선택), 취소·변경 마감 안내, 대기 신청 목록, 승인된 예약에서 바로 "라이브 준비"
- 라이브 세션을 만들면 **예약 때 고른 상품이 상품번호 1번부터 자동 등록**됩니다. (준비 불가 상품 제외)

### 창고(스튜디오) 관리자
- **상품 관리** (메뉴 추가): 상품 수정(이름·카테고리·가격·재고·수수료·설명·이미지), 누적 예약/라이브 판매 횟수, **다가오는 예약의 판매 예정 수량과 재고 부족 경고**. 상품 등록 화면에서 셀러에게 보이는 카드를 미리 확인.
- **예약 정책 설정** (창고(스튜디오) 정보 → 예약 정책 설정): 즉시 확정, 시작 단위(정시/30분), 예약 사이 준비시간, 최소·최대 이용 시간, 최소 몇 시간 전 예약, 최대 며칠 앞까지, 셀러 직접 변경·취소 마감, 예약 안내사항
- **예약 현황**: 판매 예정 상품과 수량 확인, 상품별 **준비 가능/불가 표시**(셀러에게 알림), 정기·일정 변경 표시, 예약번호 검색. 승인하면 요청 상품은 자동으로 "준비 가능".

### 서버 규칙 (`src/lib/booking-engine.ts`, `src/lib/booking.ts`, `src/lib/booking-actions.ts`)
- 운영 시간대·휴무일·시작 단위·최소/최대 시간·선예약 기간·최소 사전 시간·**준비시간 포함 중복**을 서버에서 최종 검사
- 같은 창고(스튜디오)의 예약 생성·변경·승인은 **PostgreSQL advisory lock**으로 한 줄로 처리해 동시에 같은 시간을 잡을 수 없습니다.
- 셀러는 승인된 예약을 마감 시간 전까지만 직접 취소·변경할 수 있고, 승인된 예약을 셀러가 바꾸면 다시 승인 대기로 돌아갑니다(즉시 확정 공간 제외).
- 예약이 취소·거절되면 방송 전 라이브 세션도 함께 취소됩니다.

## 2026-11-11 정산 · 배송비 · 공급가 보완 (적용 방법)

> `dev.bat`(또는 `db-sync.bat`)으로 서버를 다시 켜면 새 컬럼이 DB에 자동 반영됩니다. 기존 데이터는 그대로 유지됩니다.

### 수익 분배 (판매 시점 확정)
- 주문할 때 상품 줄마다 **플랫폼 수수료 · 브랜드 공급대금 · 창고(스튜디오) 몫 · 셀러 몫**을 계산해 `OrderItem`에 저장합니다. 이후 수수료율 · 공급가 · 셀러 수수료를 바꿔도 이미 팔린 주문은 바뀌지 않습니다. (예전 주문은 기존 방식으로 계산)
- **창고(스튜디오) 셀러 공급가**(`FacilityProduct.supplyPrice`, 권장): 창고는 공급가를, 셀러는 `판매가 − 판매 수수료 − 공급가`를 받습니다. 브랜드 위탁 상품이면 창고 몫은 `공급가 − 브랜드 공급가`. 공급가를 비우면 기존 셀러 수수료(정률/정액) 방식.
- 셀러는 방송 상품 가격을 **공급가 · 브랜드 최저 판매가 이상**에서만 바꿀 수 있고, 수수료 방식 창고 상품은 가격을 바꿀 수 없습니다. 판매 수량은 실제 재고(창고 · 브랜드)를 넘을 수 없습니다.
- 창고(스튜디오)가 직접 등록한 상품도 판매 시 **창고 실재고를 차감**하고 취소 시 되돌립니다.
- 각 계정의 정산 화면에서 **판매별 내 수익**을 봅니다: 셀러(`/seller/settlements`), 창고(`/facility/settlements`), 브랜드(`/brand/settlements` 판매별 공급 수익).

### 배송비 (셀러 설정)
- 방송 상세 → **배송비 설정**: 무료(상품가 포함) · 유료 · 조건부 무료(n원 이상). 주문 시 확정되어 `Order.shippingFee`에 저장되고, 판매 수수료 없이 셀러 몫으로 정산됩니다. 전체 취소 · 환불 시 함께 환불됩니다.
- 모든 주문은 배송지가 필수입니다.

### 셀러 정산 계좌
- 셀러 · 중간관리자 **설정 → 정산 계좌**. 등록된 계좌를 바꿀 때는 현재 비밀번호 확인 + 최고관리자 알림. 관리자 판매 정산 화면과 이체용 CSV에 셀러 계좌가 표시됩니다.

### 운영 규칙
- 라이브 방송은 **승인된 예약으로만** 만들 수 있습니다. (방송 시간은 예약 시간으로 기본 설정)
- 셀러별 **승인 대기 예약 최대 건수**(기본 10건)와 **이메일 인증 필수**(기본 꺼짐)를 `/admin/policy`에서 정합니다.
- 결제 대기에서 30분 넘게 멈춘 주문은 자동으로 닫고 재고를 되돌립니다(주문 접수 시 · `/api/cron/bookings`).
- 같은 주문의 취소 · 상태 변경은 동시에 처리되지 않습니다(중복 결제 취소 방지).
- `PAYMENT_PROVIDER`에 구현되지 않은 결제사(예: `toss`)를 넣으면 결제가 막힙니다. 실제 PG 연동 전까지는 `mock` 유지.

## 개발 서버 · DB 동기화 (Windows)

- `dev.bat` — 이 프로젝트의 남아 있는 개발 서버를 먼저 정리한 뒤 3007 포트로 시작합니다. `npm run dev` 는 시작 전에 `scripts/ensure-db.mjs` 를 실행해 `schema.prisma` 가 바뀌었으면 Prisma Client 재생성과 `prisma db push` 를 자동으로 합니다.
- `stop-dev.bat` — 창을 닫았는데도 http://localhost:3007 이 계속 열려 있을 때 실행합니다. 3007 포트를 쓰는 프로세스와 이 폴더에서 실행된 node 프로세스(백그라운드 AI 도구가 띄운 서버 포함)를 종료하고, 무엇을 종료했는지 보여 줍니다.
- `db-sync.bat` — 여러 화면에서 "데이터를 불러오지 못했습니다" / "일시적인 오류가 발생했습니다"가 뜨면 실행합니다. 서버 종료 → Prisma Client 재생성 + DB 구조 반영 → 서버 재시작 순서로 진행합니다.
- 원인: Windows 에서는 실행 중인 서버가 Prisma 엔진 파일을 잠가 `prisma generate` 가 실패합니다. 그러면 코드와 DB 구조가 어긋나 여러 화면이 동시에 오류를 냅니다.
